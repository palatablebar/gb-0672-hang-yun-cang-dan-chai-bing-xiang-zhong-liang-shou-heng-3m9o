# 航运舱单拆并箱与重量守恒

给货代单证员使用。主提单与分提单拆并形成有向无环关系，件数和净毛重逐层守恒。

七个业务模块：舱单采信、包装映射、拆并编组、危险品检查、净毛重核验、报关对账、版本封存。另设第八个工作台「拆并预演」(`/rehearsal`)，在船开前对拆并箱指令做只读裁定，不直接改正式舱单。

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
```

访问 http://localhost:18241 。启动直接载入现场脏批。切换干净样例和旧编码样例可对照核验。干净批42个节点、6个主单，件数240、净重2400kg、毛重2640kg；现场脏批包含父级缺失、依赖环、危险品不相容及1kg毛重差异，封存状态为待处理。

## 拆并预演裁定

单证员在船开前接到拆并箱指令，不能先改正式舱单再试。预演工作台逐张主单裁定两种方案：`hold`（整票不动）与 `split`（按箱容拆到子层）。每张主单给出：

- 采用方案与箱容上限（件数/毛重 kg，可整票或单票覆盖）；
- 箱内容量与件净毛重是否**同时成立**（任一超限或守恒差异即判不成立）；
- 需要补证的位置（拆层变更上级申报来源、危险品缺 UN 编号等）；
- 裁定结果 `READY`（可进入正式执行）/ `SUPPLEMENT`（补证后可执行）/ `BLOCKED`（阻断）。

关键边界：

- **只读**：预演只读取当前舱单批次，`records` 与原申报依据不变；正式应用产出的是新版本批次（`AP-` 前缀），旧批次永不覆盖。
- **幂等**：同一舱单 + 同一指令指纹只保留一条预演，重复提交不新增第二套裁定。
- **局部重算**：指令修订到达后，按主单指纹比对，只重算受影响主单，未变化主单沿用上版裁定并标记 `reused`，修订历史留痕。
- **原子应用**：`POST /api/rehearsals/{id}/apply` 在单事务内写新批次与应用记录，任何失败整体回滚，旧版关系保留、不留半套；补证类裁定须确认补证项，阻断主单未清除前拒绝应用；乐观版本号陈旧提交返回 409。

接口：`POST /api/rehearsals`（体含 `run_id`、可选 `instruction.limits` 与 `instruction.items`，不传 items 用内置演示指令）、`GET /api/rehearsals`、`GET /api/rehearsals/{id}`、`POST /api/rehearsals/{id}/apply`。

各模块页面对应 `/<模块英文名>`，各模块执行入口为 `POST /api/<模块英文名>`，不传参即可独立演示。完整运行 `POST /api/runs` 支持 `dataset`（dirty/clean/legacy）、`csv_text` 与 `overrides` 参数。批次历史 `GET /api/runs`，详情 `GET /api/runs/{run_id}`。

同输入与规则版本生成相同批号，只保留一条批次。复核入口 `POST /api/runs/{run_id}/review` 提交当前 `revision`，陈旧提交409。归档包只有一个下载入口 `GET /api/export/{run_id}`，含证据和运行摘要。原始隔离在页面同屏显示。

SQLite使用命名卷，容器重启后保留历史。要重建演示可在Compose中改用新的卷名称，保留旧卷。

源码在 `app/`，样例在 `sample_data/`，测试在 `tests/`；定义见 `docs/DATA-DICTIONARY.md`，模块和边界测试对应关系见 `docs/DEPTH.md`。输入上限2MB，属于离线复核工具。

采信页支持上传或粘贴CSV。完整源字节与参数随批次持久化，跨页通过run_id读取同一结果。`POST /api/runs/{run_id}/rerun` 读取该批不可变输入快照重新计算，规则未变时批号不变。切换另一示例则创建或复用另一批次。
